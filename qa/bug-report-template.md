# Шаблон отчета об ошибке (Bug Report Template)

## Формат заголовка
`[Компонент][Окружение/Разрешение] Краткое описание дефекта`  
*Пример:* `[Cart][320px] Кнопка «Оформить заказ» выходит за границу экрана`

---

## Поля баг-репорта

- **ID дефекта**: `BUG-CC-XXX`
- **Приоритет**: `Critical` | `High` | `Medium` | `Low`
- **Окружение**:
  - Браузер / Клиент: Chrome 130 / Postman v11
  - Разрешение экрана: 320×640 (Mobile) / 768×1024 (Tablet) / 1200×900 (Desktop)
  - Стенд: `http://localhost:8080` (Branch `main`)
- **Предусловия**:
  - Авторизован под ролью `customer@cherrycake.com` / Неавторизованный гость
  - Выбран регион `UZ`
  - В корзине находится 1 товар

### Шаги воспроизведения
1. Перейти в каталог `/api/products?region=UZ` или на витрину.
2. Добавить товар ID `1` в корзину.
3. Открыть панель корзины (ширина 320 px).
4. Нажать кнопку «Оформить заказ».

### Ожидаемый результат
Форма чекаута корректно адаптируется, горизонтальный скролл отсутствует, фокус устанавливается на первое поле «Имя».

### Фактический результат
Появляется горизонтальная прокрутка страницы на 35 px, правая часть кнопки обрезана.

### Вложения / Логи
- Скриншот: `assets/bug-screenshots/BUG-CC-01.png`
- Ответ API (JSON):
```json
{
  "status": 400,
  "message": "Validation failed"
}
```

---

## Градация приоритетов (SLA)
- **Critical**: Невозможно завершить основной пользовательский сценарий (оформление заказа, бронирование столика, расчёт суммы); падение сервера 500; искажение финансовых данных `total`.
- **High**: Нарушение бизнес-правила (не применился максимальный промокод, не сработал лимит вместимости слота, контраст текста < 4.5:1, тач-цель < 44 px).
- **Medium**: Отсутствие обязательного `data-testid`; несоответствие отступов токенам CSS; отсутствие состояния `loading` / `empty`.
- **Low**: Косметические дефекты, опечатки, смещение нефункциональных иконок на 1-2 px.
