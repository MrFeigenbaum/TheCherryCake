3. Чеклист на каждую страницу
Цвета, шрифты и отступы взяты из токенов, своих значений нет.
Состояния компонентов: hover, focus (виден), error, disabled.
Клавиатура: все действия доступны, порядок фокуса логичный.
Контраст текста не ниже 4,5:1; у полей есть подписи; кнопки-иконки с aria-label.
Ширины 320, 768 и 1200 px: нет горизонтального скролла; зум 200 % не ломает вёрстку.
Области нажатия не меньше 44 px.
Lighthouse Accessibility не ниже 90; axe без критичных ошибок.
Экраны совпадают с макетами AS.

5. Что проверяем в чекауте
Обязательные поля: имя, телефон, email, Order Date. Пустое значение показывает ошибку под полем.
Телефон и email неверного формата, дата в прошлом: ошибка с понятным текстом.
Ошибка API (например 400) показывается как сообщение, а не как пустой экран.
Итог на экране равен ответу API; кнопка «Подтвердить» неактивна, пока форма не валидна.
После заказа показан номер заказа.
6. Кого ждёшь и кому отдаёшь
Ждёшь макеты от AS (Ср недели 1) и витрину /ui-kit от FE1 (Пт недели 1). Баги по витрине отдаёшь FE1 до понедельника.
Для регресса недели 4 нужны готовые страницы FE2 и FE3. Баги заводишь в GitHub Issues по шаблону QAJ.
