1. Зачем этот документ
Десять человек пишут один продукт на двух языках. Если бэкенд назовёт сумму НДС vat_total, фронт — taxAmount, а в PDF будет «НДС, сумма» — на сверке цифр все потеряют время. Этот документ — единый словарь. Имя, которое здесь записано, используется везде: в БД, в Java, в JSON, в JS, в CSV/PDF и в тестах. Добавить новое имя можно только с записью сюда.
Главное правило
Одна сущность — одно имя на всех слоях. Меняется только стиль написания: snake_case в БД, camelCase в Java/JSON/JS. vat_amount ↔ vatAmount — это одно имя.
2. Принципы именования
2.1. Общие
Имя описывает смысл, не тип: не priceNum, а unitPrice; не dataList, а products.
Никаких сокращений кроме общепринятых: id, url, dto, api, vat, jwt. Не: qty (пиши quantity), amt, cnt, usr.
Булевы — с is/has/can: isAvailable, hasDiscount, canCancel.
Коллекции — во множественном числе: items, slots, regions.
Деньги — всегда с суффиксом Amount или Fee или Price или Total: vatAmount, deliveryFee, unitPrice, lineTotal. Ставки — с суффиксом Rate и хранятся как доля (0.12), не процент.
Идентификаторы внешних сущностей — <сущность>Id: productId, regionId, timeSlotId.
Даты: <что>Date (дата), <что>Time (время), <что>At (timestamp): orderDate, startTime, createdAt.

3. Глобальные перечисления (enum)
Значения — заглавными, одинаковые в Java-enum, в JSON и в JS-константах. Фронт не придумывает свои: const OrderStatus = { NEW: "NEW", … }.
Enum
Значения
Описание
RegionCode
UZ, KZ, RU, (добавить по таблице курса)
Код страны, ISO 3166-1 alpha-2. Единственный способ передать страну: query ?region=UZ
CurrencyCode
UZS, KZT, RUB
ISO 4217. Берётся из regions, фронт не хранит свои
OrderType
PICKUP, DELIVERY
Способ получения заказа
OrderStatus
NEW, CONFIRMED, DONE, CANCELLED
Жизненный цикл заказа. Переходы: NEW→CONFIRMED→DONE; любой→CANCELLED
BookingStatus
CONFIRMED, CANCELLED
Статус брони столика
Role
CUSTOMER, VIEWER, STAFF, ADMIN
Роли RBAC. Иерархия доступа: ADMIN ⊃ STAFF ⊃ VIEWER; CUSTOMER — обычный гость
ModifierType
SINGLE, MULTI
SINGLE — радио (выбрать один), MULTI — чекбоксы
GroupBy
REGION, MONTH
Группировка отчёта
ExportFormat
CSV, PDF
Формат экспорта отчёта
4. Денежные поля — единые имена
Эти 11 имён используются в таблице orders, в DTO CalculateCartResponse и OrderResponse, в cartSlice.totals, в колонках CSV, в KPI PDF и в тест-кейсах QA. Порядок строк = порядок расчёта.
Имя
Как считается
Описание
subtotal
Σ(unitPrice × quantity)
Сумма без НДС и скидок
vatRate
0.12
Ставка НДС страны как десятичная доля (12 % = 0.12), НЕ 12
vatAmount
subtotal × vatRate
Сумма НДС
amountInclVat
subtotal + vatAmount
Сумма с НДС. От неё считается порог скидки
discountRate
0.05
Доля скидки (5 % = 0.05)
discountAmount
amountInclVat × discountRate
Сумма скидки
deliveryFee
fee зоны или 0
Только при type = DELIVERY, иначе 0
total
amountInclVat − discountAmount + deliveryFee
Итог к оплате
unitPrice
regionalPrice + Σ modifierPriceDelta
Цена единицы с модификаторами
lineTotal
unitPrice × quantity
Сумма строки
currencyCode
UZS
Валюта всех сумм в ответе
Правила для денег
Java: только BigDecimal, scale 2, RoundingMode.HALF_UP после каждого шага.
JSON: number с двумя знаками (255.04). Не строка, не копейки, не float-мусор вида 255.0400000001.
JS: суммы с API показываем через formatMoney(amount, currencyCode); сами не пересчитываем. Для мгновенного превью в карточке можно считать unitPrice на фронте, но корзинные totals — только с API.
БД: NUMERIC(12,2) для сумм, NUMERIC(5,4) для ставок.
