3.2. Создание заказа — алгоритм
Валидация DTO (@Valid): items не пуст, quantity ≥ 1, orderDate ≥ сегодня, телефон/email по regex, при DELIVERY обязателен deliveryZoneId, при PICKUP — pickupPointId.
Вызвать priceCalculatorService.calculate(...) — цифры с фронта игнорируются полностью.
В транзакции: SELECT time_slot FOR UPDATE; если booked_count ≥ capacity → SlotUnavailableException (409).
booked_count + 1; сохранить orders + order_items со всеми суммами и снимками названий.
Сгенерировать order_number: CC-<год>-<id с ведущими нулями до 6>.
Вернуть OrderResponse. Статус NEW.
3.3. Бронирование — алгоритм
Валидация: date ≥ сегодня, time в часах работы (10:00–22:00), guests 1–12.
Найти столики с capacity ≥ guests, активные, отсортировать по capacity ASC (чтобы не отдавать 6-местный паре).
Для каждого проверить, нет ли брони со status=CONFIRMED на эту дату в окне [time−2ч, time+2ч). Первый свободный — берём.
Нет свободных → BookingConflictException (409, «Нет свободного столика на это время, попробуйте другое»).
Сохранить, сгенерировать BK-<год>-<id>, вернуть BookingResponse.
3.4. Отчёты
Один SQL с группировкой; никаких циклов по заказам в Java. Учитываются только заказы со status IN (CONFIRMED, DONE).
SELECT r.code AS label, COUNT(*) AS orders_count,
SUM(o.subtotal) AS subtotal, SUM(o.vat_amount) AS vat_amount,
SUM(o.discount_amount) AS discount_amount, SUM(o.delivery_fee) AS delivery_fee, SUM(o.total) AS total
FROM orders o JOIN regions r ON r.id = o.region_id
WHERE o.status IN ('CONFIRMED','DONE') AND o.order_date BETWEEN :from AND :to
AND (:region IS NULL OR r.code = :region)
GROUP BY r.code ORDER BY r.code;
-- groupBy=MONTH: label = to_char(o.order_date, 'YYYY-MM')
Поле ответа
Содержимое
kpi
subtotal, vatAmount, discountAmount, total — суммы по всем rows; averageCheck = total / ordersCount (2 знака); ordersCount
rows[]
label, ordersCount, subtotal, vatAmount, discountAmount, deliveryFee, total

from, to, region (или null), groupBy — эхо запроса, чтобы PDF печатал их в шапке

3.5. Экспорт
CSV: OpenCSV, UTF-8 с BOM, запятая, заголовок — ровно колонки из глоссария §9. Content-Disposition: attachment; filename=sales_<from>_<to>.csv.
PDF: OpenPDF. Шапка: «Cherry Cake — Отчёт о продажах», фильтры (период, регион, группировка), generatedAt. Блок KPI (5 чисел). График: гистограмма — рисуй через JFreeChart в PNG и вставляй картинкой (просто и надёжно). Таблица rows. Все числа — 2 знака, те же, что в JSON.
Оба экспорта берут данные из ТОГО ЖЕ метода сервиса, что и JSON. Не дублируй запрос.

5. Что показываешь на демо
Неделя 2: регистрация → логин → токен → /orders/my.
Неделя 3: в Swagger два заказа в один слот с capacity=1 → второй получает 409; бронь столика → номер.
Неделя 4: /reports/sales по регионам, затем скачать PDF — цифры совпадают.
Презентация: 1-2 минуты вместе с FE3 — живое оформление заказа с доставкой и бронь.
